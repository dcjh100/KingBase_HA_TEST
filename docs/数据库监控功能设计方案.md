# Kingbase 数据库高可用监控看板设计方案

## 1. 背景与目的
本项目旨在验证 Kingbase（人大金仓）数据库的高可用（HA）配置、读写分离及负载均衡能力。
参考现有的单元测试 (`DatabaseConnectionTests.cs`) 逻辑，我们需要构建一个可视化的 Web 监控界面，能够高频（如每秒 1 次）自动执行连接探测，实时展示连接落点、节点状态及网络信息，以便直观地验证数据库集群的运行状况。

## 2. 系统架构

*   **开发框架**: ASP.NET Core 8 MVC
*   **前端技术**: jQuery, Bootstrap 5 (利用现有项目基础)
*   **数据交互**: AJAX 轮询 (每秒)
*   **数据库驱动**: Npgsql

## 3. 功能设计

### 3.1. 核心功能
1.  **全景并行监控**: 在一个统一的仪表盘页面，**同时**展示三种核心场景的实时数据，无需切换页面或模式：
    *   **通道 A - 读写连接 (Primary)**: 验证写库连接稳定性。
    *   **通道 B - 只读连接 (Standby)**: 验证读库连接稳定性。
    *   **通道 C - 负载均衡测试 (No Pooling)**: 强制禁用连接池，验证请求是否在多个节点间随机分发。
2.  **自动循环探测**: 前端通过定时器并行发送三类探测请求。
3.  **实时信息展示 (每通道独立)**:
    *   当前连接的 **Server IP** 和 **Port**。
    *   当前数据库的 **读写状态** (`transaction_read_only`)。
    *   **响应耗时**。
4.  **统计分析**:
    *   **节点分布统计**: 实时计算并展示连接落在各个 IP 上的次数和百分比。
    *   **成功/失败计数**。

### 3.2. 界面设计 (UI Prototype)

采用 **三列式仪表盘布局**，让所有关键信息一目了然：

*   **顶部控制栏**:
    *   [启动所有监控] / [停止所有监控] 按钮 (一键控制)
    *   刷新频率设置 (全局统一，默认 1000ms)

*   **监控面板区 (Row)**:
    *   **左面板: Primary (读写)**
        *   状态指示灯 (🟢/🔴)
        *   当前 IP: `192.0.2.21`
        *   属性: `ReadWrite`
        *   *预期: 始终稳定在主节点 IP*
    *   **中面板: Standby (只读)**
        *   状态指示灯 (🟢/🔴)
        *   当前 IP: `192.0.2.22`
        *   属性: `ReadOnly`
        *   *预期: 始终稳定在某个备节点 IP*
    *   **右面板: LoadBalance (无连接池)**
        *   状态指示灯 (🟢/🔴)
        *   当前 IP: `192.0.2.23` (跳变中)
        *   **IP 分布图**: 进度条展示各 IP 命中比例 (e.g., IP1: 33%, IP2: 33%, IP3: 33%)
        *   *预期: IP 地址在多个节点间不断变化*

*   **底部日志区**:
    *   三个独立的滚动日志窗口，分别记录三个通道的最近探测结果。

## 4. 详细设计

### 4.1. 后端 API 设计

创建一个 `MonitorController`，提供以下 API：

**接口**: `GET /Monitor/CheckHealth`

**参数**:
*   `mode`: string (`primary` | `standby` | `loadbalance`)

**响应 (JSON)**:
```json
{
  "success": true,
  "timestamp": "2023-10-27T10:00:01",
  "data": {
    "serverIp": "192.0.2.21",
    "serverPort": "54321",
    "clientIp": "172.20.x.x",
    "isReadOnly": "off", // transaction_read_only
    "version": "KingbaseES V8...",
    "elapsedMs": 15
  },
  "error": null
}
```

### 4.2. 数据库探测逻辑 (C#)

复用 `DatabaseConnectionTests.cs` 中的核心 SQL：

```sql
SELECT 
    inet_server_addr() AS server_ip,
    inet_server_port() AS server_port,
    current_setting('transaction_read_only') AS read_only_status,
    version() AS version
```

**连接字符串处理**:
*   如果模式为 `loadbalance`，需要在基础连接字符串后追加 `;Pooling=false`，确保每次请求都建立新连接以触发负载均衡策略。

### 4.3. 前端逻辑 (JavaScript)

```javascript
var monitorInterval;
var statsLB = {}; // 负载均衡统计

function startAllMonitors() {
    monitorInterval = setInterval(function() {
        // 并行发起三个请求
        checkChannel('primary', '#panel-primary');
        checkChannel('standby', '#panel-standby');
        checkChannel('loadbalance', '#panel-lb');
    }, 1000);
}

function checkChannel(mode, panelId) {
    $.ajax({
        url: '/Monitor/CheckHealth',
        data: { mode: mode },
        success: function(res) {
            updatePanel(panelId, res);
            if (mode === 'loadbalance') {
                updateLBStats(res.data.serverIp);
            }
        }
    });
}
```

## 5. 预期效果

通过全景仪表盘，用户可以：
1.  **对比验证**: 一眼看出 Primary 连接和 Standby 连接是否指向了不同的 IP（验证读写分离）。
2.  **动态观测**: 看着 LoadBalance 面板的 IP 不断跳变，而 Primary 面板保持静止，形成鲜明对比，直观验证负载均衡配置生效。
3.  **故障可视化**: 如果某个节点宕机，LoadBalance 面板的 IP 分布将不再包含该节点 IP，直观展示故障剔除能力。
